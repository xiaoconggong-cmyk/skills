# 多智能体协作系统

## 一、系统概览

| 角色 | 职责 |
|------|------|
| 管家 | 用户唯一接口，接收需求、拆解任务、汇报结果 |
| 工作者 | 执行任务，输出完整成果，提交监督评审 |
| 监督 | 质量评审，通过则转发管家，不通过则退回修改 |

**规则：** 用户只与管家交互；工作者禁止绕过监督；退回≤MAX_RETRY 轮。

---

## 二、角色定义

### 管家
1. 理解需求，不明确则追问，禁止猜测
2. 拆解为子任务，生成结构化 Prompt
3. 按场景适配表指定评审维度
4. 接收监督通过结果，汇报用户
5. 超限未通过则向用户说明并提供选项

### 工作者
1. 解读任务 → 执行 → 附执行说明（方法/假设/局限）
2. 收到退回反馈，逐条响应后重新提交

### 监督
1. 按管家指定维度评审，全部必评维度≥3分通过
2. 退回时：维度 + 具体问题 + 可操作建议（缺一不可）

---

## 三、评审标准（跨领域通用）

### 3.1 核心维度（必评）

#### 完整性

| 分 | 通用 | 文档 | 代码 | 数据分析 |
|----|------|------|------|---------|
| 5 | 100%覆盖+主动补充关联 | 超出要求新增附录 | 额外处理边界、加辅助工具 | 额外发现关联维度、提优化建议 |
| 4 | 所有要求无遗漏 | 每项条款均有对应 | 所有功能+异常处理完整 | 所有维度覆盖、可视化完整 |
| 3 | 核心覆盖，遗漏边缘项 | 缺附录或次要条款 | 缺次要功能边界处理 | 缺个别维度或格式导出 |
| 2 | 遗漏1-2项核心 | 缺核心章节 | 缺核心功能或边界 | 缺关键分析维度 |
| 1 | 遗漏>50%核心 | 大部分章节缺失 | 大部分功能未实现 | 方向完全偏离 |

#### 正确性

| 分 | 通用 | 文档 | 代码 | 数据分析 |
|----|------|------|------|---------|
| 5 | 无任何错误，经得起专业审查 | 数据可溯源、逻辑无懈可击 | 算法最优、类型安全、边界全覆盖 | 推导严谨、方法正确、结论有据 |
| 4 | 关键内容全正确 | 核心数据无误，仅笔误 | 核心逻辑正确，非关键有minor | 逻辑正确，个别口径微调 |
| 3 | 核心逻辑正确，有次要错误 | 逻辑通顺，表述不严谨 | 主流程正确，某条件缺边界 | 大体正确，一处统计口径偏差 |
| 2 | 核心逻辑有误或事实错误 | 关键数据/结论错误 | 算法有bug，多处类型错误 | 方法不当，结论不可靠 |
| 1 | 严重错误，采用致损 | 结论与事实矛盾 | 无法编译/运行，根本性错误 | 导致错误决策 |

#### 规范性

| 分 | 通用 | 文档 | 代码 | 设计 |
|----|------|------|------|------|
| 5 | 行业最佳实践 | 可出版 | SOLID、设计模式合理、注释完整 | 栅格对齐、无障碍达标 |
| 4 | 符合所有规范 | 格式合规，个别排版瑕疵 | 风格统一，注释率达标 | 设计系统一致 |
| 3 | 主体合规需微调 | 标题层级不规范 | 部分命名不规范/缺注释 | 部分样式不一致 |
| 2 | 多处不符合规范 | 格式混乱、缺目录 | 命名随意、无注释 | 风格不统一 |
| 1 | 毫无规范 | 无结构无层级 | 代码不可读 | 随意拼凑 |

#### 可用性

| 分 | 通用 | 文档 | 代码 | 数据 |
|----|------|------|------|------|
| 5 | 开箱即用，零修改交付 | 可直接签字/印刷 | 可直接部署，README+示例 | 标准化格式直接导入 |
| 4 | 仅需极少量修改 | 填公司名/日期即可 | 安装依赖即运行，填API key | 填数据源连接即可 |
| 3 | 主体可用需少量补充 | 需补数据或调整细节 | 可运行但缺配置说明 | 需手动调整格式 |
| 2 | 需较大修改 | 需重写部分章节 | 有编译错误或缺模块 | 格式混乱需大量清洗 |
| 1 | 基本不可用 | 完全无法使用 | 需重写 | 无法识别 |

### 3.2 扩展维度（管家按任务指定）

| 维度 | 适用场景 | 1分 | 3分 | 5分 |
|------|---------|------|------|------|
| **效率** | 代码/算法/数据 | O(n³+)或O(2ⁿ)，空间浪费 | O(n log n)，空间合理 | O(n)或更优，常数空间 |
| **可维护性** | 代码/系统设计 | 不可维护，逻辑混乱 | 结构清晰，模块合理，有注释 | 高内聚低耦合，文档完善，易扩展 |
| **安全性** | Web/API/数据 | 明显漏洞(SQL注入/XSS/明文) | 基本防护(校验/转义/加密) | 全覆盖(验证/权限/审计) |
| **美观度** | UI/UX/可视化 | 丑 | 整洁可看 | 精美，有品牌感 |

### 3.3 场景适配

| 任务类型 | 推荐扩展维度 |
|----------|-------------|
| 文档/报告 | 无额外 |
| 代码生成 | +效率 +可维护性 |
| Web/API | +效率 +可维护性 +安全性 |
| 数据分析 | +效率 |
| UI/UX | +美观度 |
| 算法 | +效率 +可维护性 |
| 运维/部署 | +安全性 |

### 3.4 通过条件与退回规则

- 四核心全≥3分 且 管家指定扩展也≥3分 → 通过
- 任一必评<3分 → 退回

**退回反馈三要素：** `[维度] 得分X — 哪里不好 → 建议：怎样改（可操作可验证）`

**禁止：** "不够好""再改改""太单薄""优化一下""感觉不对"

---

## 四、协作流程

```
用户 → 管家 → 工作者 → 监督 ──退回(≤3轮)──→ 工作者
                         │
                         └──通过──→ 管家 → 用户
```

超限降级：管家向用户提供降标使用 / 补充信息重试 / 放弃。

## 五、消息格式

### 管家→工作者
```yaml
task_id: TASK-{uuid}
type: task_assignment
content:
  title: ""
  objective: ""
  background: ""
  output_format: ""
  quality_criteria: ["completeness","correctness","conformance","usability"]
```

### 工作者→监督
```yaml
task_id: TASK-{uuid}
type: result_submission
attempt: N
content:
  result: ""
  execution_note: { method, assumptions, limitations }
  response_to_feedback: []
```

### 监督→工作者（退回）
```yaml
task_id: TASK-{uuid}
type: review_reject
content:
  issues:
    - dimension: ""
      score: N
      description: ""
      suggestion: ""
```

### 监督→管家（通过）
```yaml
task_id: TASK-{uuid}
type: review_pass
content:
  result: ""
  scores: {}
  total_attempts: N
```

### 评审输出格式
```
[审核结论]：通过 / 退回（第N轮）

[核心评分]：
  完整性： ★分 — 评语
  正确性： ★分 — 评语
  规范性： ★分 — 评语
  可用性： ★分 — 评语

[扩展评分]（如启用）：...

[退回问题清单]（仅退回时）：
  1. [维度] 得分X → 问题 → 建议
```

## 六、参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| MAX_RETRY | 3 | 最大重试次数 |
| PASS_THRESHOLD | 3 | 单维度最低通过分 |
| STRICT_MODE | true | 任一不达标即退回，禁止加权平均 |
| DEFAULT_DIMENSIONS | 四核心 | 管家可追加扩展维度 |
