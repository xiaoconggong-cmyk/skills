# PPT 多智能体自动生成系统 v7.2

> **核心转变**：v5→v6.1 一直在"加约束"——结果 AI 机械套规则，仍溢出、仍空页、仍千篇一律。
> v7.0 改为 **知识驱动 + 联网研究 + 自我优化**：
> - 让 Agent **理解** PPT 设计原理，而不是死记规则；
> - 生成前 **联网搜索** 当前最佳实践，动态吸收；
> - 生成后 **自检 → 查问题 → 搜方案 → 回填知识库**，形成进化闭环。
> **唯一的硬约束**只剩"内容不得溢出画布"（会物理裁切），其余全部交给设计判断力。

## 一、为什么是 v7.0

| 版本 | 思路 | 结果 |
|------|------|------|
| v5 | 硬性坐标模板 | 所有页一模一样 + 标签悬空 |
| v6 / v6.1 | 约束清单（22 条禁止规则）| AI 套规则但**不理解设计**，仍溢出、仍空页 |
| **v7.0** | **知识 + 研究 + 自我进化** | Agent 懂原理、会查新、能从错误中学习 |

**v6.1 暴露的真实问题**（来自 `第二周工作周报.pptx`）：
1. **第 3 页文字溢出画布**：内容堆到 Y=9.29"，而画布只有 7.50"——7 条要点 + 验证挤一页，Skill 的"溢出策略"只是建议，没强制。
2. **第 1 页封面太空**：内容从 Y=2.55" 才开始，上半页全空，只有 64% 利用率。
3. **第 11/12/13 页内容稀薄**：表格/结论只有几行，下方大片空白。

**根因**：规则管不住"该换页时没换页""该填满时没填满"。需要的是**设计判断力 + 硬溢出闸 + 空页美学策略**，而不是堆更多禁止项。

## 二、PPT 设计知识库（知识，而非约束）

> 以下是从专业设计资料（含 2025–2026 最新趋势）提炼的**设计原理**。Agent 应理解并灵活运用，不是逐条打勾。

### 2.1 视觉层级（Visual Hierarchy）
- 观众眼球先到**最大、最亮、最对比**的元素。每页先确定"主角"，让它最突出。
- 三级信息：主信息（最大）→ 次信息（中等）→ 支撑细节（最小）。不要所有文字一样大。
- 位置暗示顺序：左上 → 右下（Z 字阅读动线）。标题区左上，结论可放右下。

### 2.2 留白美学（Whitespace ≠ 空）
- **主动留白**：有意为之，服务视觉目的（聚焦、分隔、呼吸）。
- **被动留白**：元素间自然缝隙，无意义。**好设计把被动留白变主动留白**。
- 学术/商务 PPT 合理留白占比约 **35%–40%**；结论/封面页可达 50%–60%（这是特点，不是缺陷）。
- **三条留白用法**：
  1. 模块间留白 > 模块内留白（用间距区分段落，而非细线）。
  2. 层级留白梯度：标题↔正文间距 > 正文↔说明间距。
  3. 焦点留白：单页只有一个核心结论时，让它占 40%–50% 面积，其余留白。
- 留白不足补救：**删 30%**。长段→图标+短句；复杂表→拆多图。

### 2.3 色彩运用
- 专业演示配色 **≤3 主色 + 中性色**。高对比（深字浅底）保证可读性。
- 颜色承载含义：主色=品牌/主题，辅色=标题/形状，强调色=关键词/数据点（克制使用）。
- 投影亮度通常只有屏幕 60%，明度差需 >70%。

### 2.4 排版构图
- **三分法（Rule of Thirds）**：关键元素放在九宫格分割线交点，比居中更有张力。
- **网格系统**：隐形参考线统一元素摆放，保证全篇一致性。
- 文字精简：**每页 ≤6–7 行，每行 ≤15 字**（中文）。一页一观点。
- 字体：标题/正文各一种，最多两族。**正式报告首选衬线宋体**（`宋体`，经典、权威、屏印皆宜）；可用**楷体**作书法感标题/强调（≤2 族）。无衬线（微软雅黑/思源黑体）屏显更清晰。用户明确指定"宋体或楷书"。
- ⚠️ **中文必须显式设 `a:ea` 字体**：`run.font.name` 在 python-pptx 只写 `a:latin`，不写中文 `a:ea`，导致中文走系统默认字体（跨机器渲染漂移）。务必用 `set_run_font()` 同时写 latin/ea/cs（见 §11.1 字体铁律）。
- 行距 1.2–1.5×，段间距为行距 1.5–2×。

### 2.5 信息可视化
- 流程/对比/层级 → 用 SmartArt、自定义形状、信息图替代纯文字。
- 图表：柱/条用于比较，线用于趋势，饼≤6 块。标注清晰，关键值加粗/变色突出。
- 图片：高清、相关、风格统一；不用廉价素材图；图片不加边框干扰。
- **⭐ 实验图/结果图必须配「图怎么看」口语化讲解（汇报口径）**：插入任何图表/实验结果图时，在图下方用 1–3 句话写明「这张图在展示什么 + 怎么向领导/听众口头说明」（如"图怎么看：彩色散点被自动分成三类，× 是质心；汇报口径：没人贴标签，我按长相把同学分几桌"）。否则受众看不懂图、汇报人无法口头说明，图就成了装饰。**配套函数见 §10.2 `add_figure_card`**。

### 2.6 一致性（Consistency = 专业感）
- 全篇统一：字体字号层级、配色、间距规则、图标风格、圆角半径、页码位置。
- 观众不应觉得"每页来自不同演示"。一致性降低认知负荷。

## 三、联网研究协议

> **核心思想**：设计潮流在变，静态规则会过时。Agent 在每次生成前应联网检索当前最佳实践，动态吸收，而不是只靠本文件。

### 3.1 何时触发联网研究
| 触发条件 | 研究动作 |
|---------|---------|
| 新主题/新风格首次生成 | 搜"该领域 PPT 设计风格 + 年份" |
| 自检发现某类反复出错（如空页）| 搜"该问题的解决方案" |
| 用户指定风格（学术/商务/科技感）| 搜该风格的权威规范 |
| 定期（每 N 次生成）| 搜"2025/2026 PPT design trends"更新知识库 |

### 3.2 研究关键词模板
```
通用：  "PPT design best practices {year}" / "presentation visual hierarchy"
学术：  "academic conference PPT golden rules" / "学术汇报 PPT 留白 排版"
商务：  "business pitch deck design 2025" / "周报 PPT 怎么排版"
空页：  "PPT empty slide design tips" / "PPT 留白 不是空白" / "PPT 内容少 怎么填充 线框造层次 形状叠层级 图标 引用数据"
配色：  "PPT color scheme professional" / "配色 3 色 高对比"
溢出：  "presentation text overflow fix" / "PPT 内容过多 分页"
字体：  "宋体 楷书 正式报告 排版 字号 行距" / "Songti KaiTi formal report typography"
```

### 3.3 研究结果整合
1. 从搜索结果提炼 **2–4 条可操作要点**（不是全文抄入）。
2. 与本知识库对照：一致的强化，冲突的记入"待复核"，新颖的加入知识库。
3. 在本会话生成中**立即应用**这些要点。

### 3.4 闭环示例（关键：问题 → 定向搜索 → 回填）
> 自我优化循环不是"开环搜一次"，而是**每出现新失败模式就针对性搜一次**。
- 发现 v6.x 把第 5/7 页生成成"仅标题、正文全空"的**空体页** → 搜索"PPT 内容少 怎么填充" → 提炼手法：线框造层次 / 形状叠层级 / 放大图形 / 图标点缀 / 引用数据 / 色块占位 → 回填第六章 + 自检新增 `detect_empty_body`。
- 用户指定"宋体或楷书" → 搜索"宋体 楷书 正式报告 排版" → 确认宋体为正文首选、楷体可作标题强调 → 回填第二章 2.4 与第八章字体规范。
- 近似行高估算存在"门禁过、PPT 里仍微溢出"残差 → 改用 PIL 加载系统 `simsun.ttc` **真实度量** → 回填 5.4。

## 四、PPT 制作全流程

> 好 PPT 是**结构化流程**的产物，不是"画几页"。Agent 严格按此流程走。

```
阶段 1：规划（Planning）
  ├─ 明确目标：告知？说服？汇报？→ 决定信息密度与语气
  ├─ 分析受众：技术专家 / 领导 / 同行 → 决定深浅与风格
  └─ 锁定核心信息：观众看完只记得一句话是什么？

阶段 2：结构（Structuring）
  ├─ 选叙事框架：金字塔(结论先行) / 时间轴 / 问题-方案 / 对比
  └─ 列大纲：封面→目录→章节过渡→核心内容→总结→结束

阶段 3：分页（Paging）★ 关键防溢出
  ├─ 按"一页一观点"把大纲切成幻灯片
  ├─ 估算每页信息量：超过 7 行 / 500 字 → 必须再分页或降密度
  └─ 标记每页类型：cover / toc / transition / content / data / summary

阶段 4：视觉（Visual Design）
  ├─ 选布局框架（见第七章，根据内容类型灵活选）
  ├─ 定视觉元素：需不需要图/表/流程图/图标
  └─ 应用知识库原则：层级、留白、配色、一致性

阶段 5：生成（Generation）
  ├─ 用 python-pptx 按方案渲染
  ├─ 每页渲染后立即做"本地溢出预检"（见第五章）

阶段 6：自检与优化（Self-Check）★ 见第十一章
  ├─ 跑后处理脚本：溢出/空页/配色/同质化检测
  ├─ 发现问题 → 联网搜方案 → 修复 → 回填知识库
  └─ 输出最终 PPT
```

## 五、溢出防护机制（唯一硬约束）

> 这是**唯一不可违反的硬约束**——超出画布的内容会被物理裁切，观众看不到。
> 其余所有约束降为"知识/建议"，唯独溢出是"闸"。

### 5.1 画布边界（绝对不可越过）
```
画布（默认 4:3）：10.00" × 7.50"（4:3）
安全区：左 ≥ 0.14"   右 ≤ 9.69"
       上 ≥ 0.19"   下 ≤ 7.30"（正文/任何可视内容不得超出 7.30"）
页码：右下角 (9.40", 7.10")

画布（16:9 宽屏，用户常用，优先确认）：13.333" × 7.50"
  说明：高度仍为 7.50"，仅宽度加宽 → 纵向坐标/安全下边界(7.30")完全不变，
        只需把横向常量放大；高度不变意味着所有 y 坐标可原样复用。
  SAFE_RIGHT = 13.19    PAGE_NUM_X = 13.0    内容统一宽度建议 CW = 12.4（x=0.6 起）
  add_section_footer 的分割线 x2 改为 12.9；add_divider 大序号右移约 x=9.8
  表格/列表/卡片的右侧边界随之拉宽（col_widths 与 w 等比例放大，居中或左齐）
  溢出豁免阈值：check_overflow 里页码豁免条件改为 x > 12.6 and y > 7.0
```

### 5.2 预渲染溢出检测（渲染每页后必跑）
```python
def check_overflow(slide, SAFE_BOTTOM=7.30):
    """渲染后立即检查本页内容是否超出安全下边界。
    注意：页码/页脚位于 7.30"–7.50" 页脚区，属合法存在，需豁免。"""
    violations = []
    for shape in slide.shapes:
        x = shape.left / 914400.0
        y = shape.top / 914400.0
        bottom = (shape.top + shape.height) / 914400.0
        if x > 9.0 and y > 7.0:   # 右下角页码豁免
            continue
        if bottom > SAFE_BOTTOM + 0.01:
            violations.append((shape.name, round(bottom, 2)))
    return violations  # 非空 = 本页必须处理
```

### 5.3 溢出处理策略（按优先级）
```
1. 分页：内容 > 7 行或估算高度 > 安全高度 → 拆成两页（首选）
2. 降密度：合并要点、删冗余、表格转图表
3. 双栏：纵向放不下 → 改左右双栏
4. 缩字号：16pt→14pt（仅最后手段，且整页统一）
5. 绝不：让元素超出 7.30"
```

### 5.4 高度估算（基于真实字体度量，必须计入段距）
> v7.0 用 `font_pt*0.55` 近似字宽，存在"门禁过了、PowerPoint 里仍微溢出"的残差风险。
> v7.1 改用 **PIL 加载系统宋体 `simsun.ttc` 真实测量**文字宽度，估算更接近真实渲染。

```python
from PIL import ImageFont
_FC = {}
def _pil_font(pt, bold=False):
    k = (round(pt,2), bold)
    if k in _FC: return _FC[k]
    px = max(1, int(round(pt*96/72)))
    p = r"C:/Windows/Fonts/simsun.ttc" if not bold else r"C:/Windows/Fonts/simsunb.ttf"
    try: _FC[k] = ImageFont.truetype(p, px, index=0)
    except Exception: _FC[k] = None
    return _FC[k]

def measure_width_in(text, font_pt, bold=False):
    f = _pil_font(font_pt, bold)
    if f is None:   # 兜底：CJK 全宽≈1em，拉丁≈0.5em
        return sum((font_pt/72.0) if ord(c)>0x2E80 else (font_pt*0.5/72.0) for c in text)
    b = f.getbbox(text); wp = (b[2]-b[0]) if b else 0
    return wp/96.0

def estimate_text_height(text, width_in, font_pt=16, line_h=1.15, space_after_pt=4, bold=False):
    usable = max(0.4, width_in - 0.12)          # 减去文本框左右边距
    tw = measure_width_in(text, font_pt, bold)
    lines = 1 if tw <= usable else max(1, math.ceil(tw/usable))
    line_in = font_pt * line_h / 72.0
    return lines * line_in + space_after_pt/72.0 + 0.06
```
> 非 Windows / 无宋体环境时 `measure_width_in` 自动回退到 em 近似，不影响流程。

## 六、空页增强策略

> 用户原话："好几页就几行字画面有点空，能不能加点其他元素、背景装饰？"
> 区分两种"空"：
> - **健康的空** = 焦点留白（结论页、封面页），是设计手法。
> - **病态的空** = 内容少又没任何视觉支撑，显得未完成。

### 6.1 判断流程
```
内容占比 < 35%？
  ├─ 是且属于"封面/结论/章节过渡" → 用焦点留白（6.2 方案 A）
  ├─ 是但属于"内容页" → 病态空，必须增强（6.2 方案 B/C/D）
  └─ 否（>35%）→ 正常，无需处理
```

### 6.2 增强手法（按推荐度）
**A. 焦点留白法（封面/结论/过渡页）**
- 大标题居中偏上 + 大量留白 + 一个视觉锚点（大序号、细分割线、弱化几何形）。
- 例：封面"第二周工作周报"用 40pt 居中，下方一条 0.5pt 灰线，底部日期——上半页不再空洞。

**B. 内容扩展法（首选，最安全）**
- 把短句拆成"加粗小标题 + 1 行说明"的列表，自然撑开纵向。
- 补充"为什么/怎么做/结果"等支撑信息（来自上下文，不臆造）。
- 例：结论页 4 条 → 每条加一行 italic 说明，页面从 4.25" 延伸到 6.5"。

**C. 视觉填充法（内容确实少）**
- 加**相关**视觉元素：图标（⚙️🔌📊）、迷你图（sparkline）、小示意图、状态卡。
- 背景装饰（克制）：**细几何线 / 角标 / 低饱和大色块（≤1 个，且在角落）**。
- 规则：装饰必须服务内容，不喧宾夺主；不用阴影/渐变/发光。

**D. 布局张力法**
- 用三分法把少量内容放在交点，其余留白形成"信息岛"——留白变成构图的一部分。
- 例：唯一关键数据放右下 1/3 处，左上留白，制造视觉张力。

### 6.3 装饰元素安全清单（允许）
```
✓ 细分割线（0.5–1pt，灰/主题色）
✓ 页码、章节小标（右上角小字）
✓ 单色低饱和几何形（圆/方，置于角落，不干扰阅读）
✓ 图标（线条型，单色）
✓ 状态卡 / 数据卡（白底细边框，非彩色块）
✗ 渐变、阴影、发光、彩色大色块、花哨角标
```

### 6.4 底部死区平衡（上重下轻）
> 真实翻车：内容集中在 0.2"–5.7"，下方 1.4" 空白 → 页面"飘"在上半部。这不是焦点留白，是布局失衡。

**判定**：内容页最大底边 < 6.0"（画布 7.50"）且非封面 → WARN `bottom_deadzone`。
**修复（按推荐度）**：
1. **页脚信息带**：细线（0.5pt 灰，y≈6.95"）+ 左章节标签（如"第二周工作周报 · 一、本周概况"），与右下页码呼应 → 视觉重心下沉、一致性增强。
2. **小结下移**：把页面既有"一句话总结"从 ~5.3" 下移到 ~6.15"，与页脚形成底部视觉簇。
3. **放大图形 / 形状叠层级**：将关键形状/圆角矩形放大占比，或叠 2–3 层形状制造纵深（来自联网研究：放大图形、形状叠层级是填空白的高效手法）。
4. **引用数据 / 图标点缀**：补一句行业数据或线条型图标（iconfont 同族），填充并提升信息量（联网研究：引用数据、icon 助力）。

> 平衡目标：内容最大底边落在 6.0"–6.9"，与页脚（6.95"）+ 页码（7.10"）形成稳定三级落点。

## 七、布局框架（灵活而非坐标模板）

> v6.1 的"固定坐标"导致千篇一律。v7.0 只给**框架原则**，Agent 在框架内根据内容自适应。
> **禁止所有页面用同一套坐标**——这是设计常识，不是规则。

### 7.1 七种内容类型 → 布局取向
| 类型 | 布局取向 | 要点 |
|------|---------|------|
| 封面 cover | 大标题 + 焦点留白 + 锚点 | 居中或左上，下方留白用线/日期填充 |
| 目录 toc | 纵向条目列表，序号对齐 | 每条一行，左对齐 |
| 章节过渡 transition | 大序号 + 章节名 + 大面积留白 | 极简 |
| 概述 compact | 标题 + 3–5 要点 + 自然留白 | 要点独立 textbox |
| 列表 standard | 标题 + 正文 + （图/表）| 图文可上下或左右 |
| 数据 data | 表格/图表 + 说明 | 表用细框，说明在侧或下 |
| 密集 dense | 多区块网格（2×2 / 2×3）| 每区块独立框 |
| 混排 mixed | 左文右图 / 左图右文 | 顶部对齐 |

### 7.2 自适应原则（必守）
1. **标题 X 按页变化**：不同页用不同起点（如 1.14"–1.39" 池），同类页可一致。
2. **正文每要点独立 textbox**：便于各自精确定位（参考真实 PPT 做法）。
3. **同类元素左对齐**：所有要点左边界一致。
4. **垂直紧密承接**：标题→副标题→正文 自然衔接，不跳层。
5. **标签/页码在内容之下**：不得悬空。
6. **溢出即分页**：见第五章。

管家（拆解任务）→ Agent-A（布局规划）→ Agent-B（视觉/配图）→ Agent-C（合并渲染）→ 监督（评审+自检）。

from pptx import Presentation

from pptx.dml.color import RGBColor

### 10.2 核心函数（保留并强化）
- `add_textbox_bold(slide, text, x, y, w, h, size, color)` — 文本框
- `add_dashed_box(slide, x, y, w, h)` — 虚线框（#9CA3AF, 0.5pt）
- `add_image_clean(slide, path, x, y, w, h)` — 纯净图片（无边框）
- `estimate_text_height(...)` — 见 5.4（计入段距）
- `add_body_textboxes_separate(slide, paras, x, start_y, width)` — **每要点独立 textbox**，返回 `(end_y, boxes)`
- `add_page_number(slide, n)` — 右下角页码
- `add_tag_label(slide, text, x, y)` — 紫色标签（宽度 `len*0.24"`）
- `check_overflow(slide)` — 见 5.2（**渲染每页后必跑**）
- `add_decoration_line(slide, x1, y1, x2, y2, color=C_DASH, w=0.5)` — 细分割线
- `add_status_card(slide, x, y, w, h, title, body)` — 白底细框状态卡
- `add_figure_card(slide, path, x, y, w, h, caption, cap_color=C_BLACK, cap_size=11.5, header=None)` — **图 + 讲解合一卡片（强烈推荐用于实验/结果图）**：虚线框包围图与文字，上方居中放图（等比 fit），下方写 `caption`（支持 `\n` 多段）。`caption` 固定写成「图怎么看：…\n汇报口径：…」两行，落实 2.5 节的"图配讲解"原则。多图画布用 `x` 错列摆放（如 3 张各 `w=3.95` 间隔 0.28；2 张各 `w=5.85` 间隔 0.6）。

### 10.3 主渲染循环（含溢出闸）
```python
def generate_pptx(plan, output_path):
    prs = Presentation()
    prs.slide_width, prs.slide_height = Inches(SLIDE_W), Inches(SLIDE_H)
    for i, slide_info in enumerate(plan["slides"]):
        slide = build_slide(prs, i+1, slide_info)
        # ★ 溢出闸：渲染后立即检测
        viol = check_overflow(slide)
        if viol:
            raise OverflowError(f"第{i+1}页溢出: {viol} —— 必须分页或降密度后重渲染")
    prs.save(output_path)
```

## 十一、自我优化循环（核心）

> 用户原话："形成一个自我优化的过程，我希望你能自己不断优化。"
> 这是 v7.0 的灵魂：**生成 → 自检 → 查问题 → 搜方案 → 回填 → 进化**。

### 11.1 生成后自检脚本（必跑，六类检测器）
> v7.0 只检溢出 → 漏掉空体页/卡片内溢出/底部死区/同质化（v7.1 补齐）。v7.2 再补两类：
> **普通文本框溢出**（卡片外的文本框也会把字溢到框外/压住下一行，v7.1 盲区）+ **字体声明自检**（自证"宋体已生效"，防止中文 `ea` 漏设的假阳性）。

```python
def self_check(prs):
    issues = []
    title_x_list = []
    for idx, slide in enumerate(prs.slides, 1):
        # 0. 溢出（FATAL，唯一硬约束）
        if check_overflow(slide): issues.append(("FATAL","overflow",idx,"Y超出画布"))
        # 1. 空体页（FATAL）
        # 2. 卡片内文字溢出（WARN）
        # 3. 普通文本框溢出（WARN，v7.2 新增，覆盖非卡片文本框）
        # 4. 底部死区/上重下轻（WARN，封面排除）
        # 5. 字体声明（WARN，v7.2 新增：任意 run 的 latin/ea 非 宋体/楷体 → 抓中文 ea 漏设）
        # 6. 同质化（WARN）：标题X重合>50%
    if detect_homogenization(title_x_list): issues.append(("WARN","homogenization",0,"标题X重合>50%"))
    return issues
```
**字体铁律**：必须用 `set_run_font(run, name)` 同时写 `a:latin` / `a:ea`(中文) / `a:cs` 三处 typeface。
> ⚠️ `run.font.name` 在 python-pptx 里**只写 `a:latin`**，中文 `a:ea` 不写入 → 中文实际走系统默认东亚字体，导致"声称宋体、实则不是"。v7.1 成品 203 个 run 全中此坑（latin=宋体、ea=None），v7.2 用 `set_run_font` 修复并加 `detect_font` 自检封死。

**处置**：FATAL（溢出/空体页）→ 终止保存、必须修复；WARN → 进入 11.2 联网搜方案修复。封面（第1页）用焦点留白，排除 `bottom_deadzone` 与 `empty_body` 误报。

### 11.2 问题记录与联网修复
检测到问题后：
1. 把问题写入 `assets/issue_log.md`（日期 + 文件 + 问题表）。
2. **按问题类型联网搜索方案**（见 3.2 关键词）。
3. 应用方案修复 PPT。
4. 若方案有普适价值 → 提炼后**回填到本 SKILL.md 知识库**（第二章）。

### 11.3 知识库进化示例
```
初始知识："留白是好的"
发现问题："第11页表格后大片空，显得未完成"
联网研究："空页用装饰线/状态卡/图标填充"
回填知识："病态空页 → 用 6.2 方案 B/C/D 增强"
下次生成：Agent 自动对低密度内容页做增强
```

### 11.4 进化触发
- 每次生成后跑 `self_check` → 有 WARN/FATAL 即进入 11.2。
- 用户反馈问题 → 直接触发对应类型研究。
- 周期性（如每 5 次生成）→ 搜最新趋势，刷新知识库。

### 11.5 可执行自优化驱动（v7.2 新增，`assets/optimize_loop.py`）
> 把上述"循环"从散文变成可运行脚本，让闭环能真正自动跑、且可当回归测试。

```bash
# 诊断任意 PPTX（默认诊断 v7.2 成品）
python assets/optimize_loop.py [pptx路径]
```
- 复用生成器的全部检测器（溢出/空体/卡片溢出/文本框溢出/底部死区/字体/同质化）。
- 输出结构化报告 + **每种失败模式→一个定向联网搜索 query**（`SEARCH_MAP`）+ 自动修复剧本（`AUTO_FIX`）。
- 自动把诊断结果追加进 `assets/issue_log.md`。
- **回归用途**：对历史问题文件（如 `第二周工作周报.pptx` 原始版）跑一遍，应抓出 `FATAL overflow 第3页`、中文 `ea=None` 字体错配、底部死区、空体页——证明闭环有效。

## 十二、监督评审

| 维度 | 检查 |
|------|------|
| 溢出 | 无任何元素超出 7.30"（**硬闸，FATAL**）|
